# Playbook: store copy and event cards

Text players read before they join: the title, the description, update lines, event cards, pass names and group posts. Growth drafts it and the owner approves it. Nothing is edited in Creator Hub until the thing it describes is live and the owner has said so.

## The description
- **First line:** what you do in the game, in the player's words, matching the first minute. This line shows in the most places.
- Then three to five short lines: the core loop, what you collect or build, what is new.
- Then the update line and any codes.
- Keep it well under the length limit. A save near the limit, especially with emojis, can be dropped without an error, so re-read the saved text after every edit.
- No words a group or platform text filter blocks. Preview before publishing.
- No promise the first minutes do not keep, no invented numbers and never "free" for a paid thing.

## Promise check (run on the title, first line and every picture caption)
1. Write what a new player sees and does in their first three minutes.
2. Strike any claim that is not on that list.
3. Lead with the real core action.

## Update lines
One line per update: what is new, when (with the time zone), and a pointer to the event card. Add the line only after the update is confirmed live: the publish run is green, the new version number is known and the switches are on.

## Codes
A code is a thank-you, written in the past tense and open to everyone: "Thanks for 1,000 visits! Code: ____". Never promise a code at a future like or favourite count, never check whether a player liked the game and never ask for a like in return for anything. Add a code's line only after the engineer confirms it works on live servers.

## Event cards
Roblox events show on the game page and can notify players who tap "Notify me".
- **Title:** the update's name, a few words.
- **Line:** what the player gets to do, with the start time.
- **Picture:** one subject, readable at phone size, from the update's real content.
- Create the card well ahead and point the description's update line at it.
- After an update goes out, the next event's card becomes the thing to promote.
- Cards are made by hand in Creator Hub unless the owner sets up an approved route. Check the limits on how many can exist at once before creating a second.

## Pass and product text
- The name says what it is. The description says exactly what it gives: numbers, durations, contents.
- A struck-through price was really the price. No countdown pressure.
- Names and descriptions are changed in Creator Hub by the owner.

## Group posts and announcements
- Short, with the one thing to do. Post only after the live check passes.
- "Notify everyone" style posts are for real updates, not for every fix.

## Release checklist (every update)
1. The publish is green and the new version is live.
2. The merged work is in that version and its switches are on.
3. The description's update line and the event card are right.
4. Then the group post, on the owner's say.
5. Log the minute for the stats reads.

## Where drafts live
`library/Growth-Agent/store-copy-<date>/`, one file per piece with the text ready to paste, and a note of when each went up.
