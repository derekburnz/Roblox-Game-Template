# Owner preferences (the defaults)

These are the working preferences this template was built around. They are defaults, not laws. During setup the coordinator shows this list and asks one question: "Keep these defaults, or change any?" The answers go into the project instructions and memory, and this file in the game's library is updated to match.

Each line has its reason, so a thread can use judgment when a case is not covered.

## How to talk to the owner
1. **Answer first, in plain short words.** The owner often reads on a phone between other things.
2. **No emojis, no dashes and no Oxford commas.** A house style: it keeps every thread sounding the same.
3. **Lists only when asked.** Short prose reads faster in chat.
4. **No decision cards in the project chat.** Ask in plain text with the options and a recommended pick. In the project chat a card press can open a reply thread and scatter the conversation.
5. **Questions go through the coordinator,** one short line each: what is needed, the options and the recommendation. The owner does not read threads.
6. **Never call something "high priority"** unless the owner said so in their own words.
7. **Never say a test works until its result is in.**
8. **A post that says "here is" a picture carries the file.**

## How work moves
9. **No new threads unless the owner says so in their own words.** Every thread costs usage, and a blanket OK does not cover new ones.
10. **Never stop.** Threads keep working through open issues and PRs. A stuck item is parked with the coordinator in one line and the thread takes the next one, in any lane. Waiting for the owner wastes the hours they are away.
11. **Auto-merge every PR once Review-QA passes it.** The review is the gate; a second wait for the owner adds delay and no safety.
12. **Publish silently, and never restart servers unless the owner says so.** A publish reaches new servers without bothering anyone. A restart disconnects every player.
13. **A switch goes on the same hour its PR publishes,** and off switches stay for rollback. Held features help nobody, and the off switch is the safety net.
14. **Every tutorial change ships behind an off switch.** The first minute decides whether a player stays, so it must be reversible in a minute.
15. **Close issues and PRs as soon as the work merges,** so the open lists show only real work.

## Where things run
16. **Studio runs only on the owner's PC through the Sync agent.** Two Remote Control sessions on one Studio collide, so one thread drives it and the others send it jobs.
17. **Uploads, store settings, keys, prices and ad budgets stay with the owner.** Threads prepare the file or the text and the owner presses the button, unless the owner hands a specific job over.
18. **Social posts (Buffer and the like) go out only on the owner's say.** A public post cannot be taken back.
19. **Claude never types passwords or codes,** and uses the owner's signed-in browser only when the owner says so.
20. **Free tools are fine; paid tools need the owner's OK.**

## Game rules
21. **Original IP only.** Mechanics can be borrowed; names, characters, art and audio are ours.
22. **Young audience by default:** no dark patterns, odds always shown, nothing truly limited, no pressure to buy.
23. **Tutorial steps are tapped by the player** (dim plus arrow), and no menu ever opens by itself.
24. **Icon, thumbnails and title promise only what the first minutes show.** Roblox's Home recommendations punish clickbait.

## Asked once at setup
- Time zone (default ET). Threads give times in it.
- The PC's name and the game folder, for Remote Control.
- Whether a Roblox group owns the game.
